一、当前存活源（2层降级，按优先级排列）
════════════════════════════════════════

① 灰鸟API  【主源】
   类型: JSON API
   地址: http://api.huiniao.top/interface/home/lotteryHistory?type=fcsd&page=1&limit=1
   特点:
   · 自带 next_code 字段 → 天然支持跨年期号回绕（12-31→次年001）
   · 单次请求只返回最新一期（limit=1）
   · 2026-08-12 实测: 存活 ✅

② 17500.cn  【备份源 · 官方级全量TXT】
   类型: 官方级数据文件（2002年至今全量）
   地址: https://www.17500.cn/getData/3d.TXT
   格式: 每行 = 期号 日期 百 十 个 ...
   特点:
   · 全量历史，可用于补漏（灰鸟 limit=1 会跳过中间期，用 17500 全量补齐）
   · 有反爬限流（偶发 429）→ 已内置重试3次 + 换UA（Chrome/Linux/urllib）
   · 与灰鸟交叉验证一致（2026204期978双源相同）
   · 2026-08-12 实测: 存活 ✅

三、防护与安全机制
════════════════════════════════════════

1. 期号合理性校验
   fetch_latest 内置校验: 凡返回期号 <= 本地CSV最新期号，一律视为
   缓存/旧数据拒绝采用，防止假数据污染历史。

2. 跨年安全
   next_issue_calc() 优先用灰鸟 next_code 字段，兜底按开奖日期
   12-31 判断回绕次年 001 期（含异常日期格式兜底，4组边界用例全过）。

3. "源活着" vs "有新区" 区分
   fetch_latest 返回 (data, alive):
   · alive=True = 至少一个源成功返回数据（即使无新期，属开奖前正常）
   · alive=False = 所有源都失败 → 页面显示橙色横幅"数据源异常"告警
   避免开奖前误报，也避免数据源全挂时静默停更。

4. 双源交叉验证
   灰鸟 + 17500 同周期号必须一致，防止单一数据源被污染。
